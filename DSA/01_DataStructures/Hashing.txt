In java, the HashMap<K,V> is basically the hash map, with a few very specific java rules and optimizations.
We need to understand two methods on keys:
- hashCode() -> gives an int "hash".
- equals() -> defines when two keys are the "same key"
Rule (contract):
- if a.equals(b) is true, then a.hashCode() == b.hashcode() must also be true.
- If you break this, HashMap will behave incorrectly (can "lose" keys)
- Keys should be effectively immutable while in the map (meaning, don't change the fields used by hashCode/equals after the insertion)

A map is just a set of key value pair. That's it. Imagine in a company you have a bunch of employees with ID numbers. I would probably
want something where I could put in an employee name and get their id number. We can create a "map"  of employee numbers to id numbers.

When defining a HashMap in java, we must first specify the type of keys and the type of values we want in our "Map".
Eg: Hashmap <String, Integer> employeeId = new HashMap <String, Integer> ();
// we can just do = new Hashmap<>(); as java automatically understands the type from previous declaration.
// This tells java that this is going to be a map of strings to integers.
The keys are String and the values are Integer.

To add a new mapping to a Hashmap, follwing this example we do:
employeeId.put ("Tirsan", 12345);         // Tirsan is the key while 12345 is value.

To get a value associated with a key, we use the get method . Eg: employeeId.get("Tirsan"); // if we print this, we will get 12345.

To check if a certain key exists in our map, we can use the containsKey method.
Eg: employeeID.containsKey("Sapkota"). This will output false. If we use Tirsan instead of sapkota, it would output true.

We can also check if a certain value exists in our map
Eg: employeeID.containsValue(678910); // this outputs false as this doesn't exist in our example. Would ouptut true for 12345.

If we do employeeId.put("Tirsan", 23456); , this would now update our key to the new value of 23456. So, put will put a key value pair if
there isn't a key already but will update the value pair if the key is already in the HashMap.

Another method is replace. If we do employeeId.replace("Sapkota", 999); Since Sapkota doesn't yet exist in the HashMap, it won't do anything.
It will however replace the value if the key does exist in the hashmap.

employeeID.putIfAbsent("Tirsan", 12345). // putIfAbsent updates the value in the HashMap if "Tirsan" already doesn't exist in the hashmap.
If it does exist, then putIfAbsent does nothing.

To remove a key, value pair, we use the remove method as employeeId.remove("Sapkota");

Also, the key value pair type must be Java Classes. They can't be primitive types. Meaning they can't be int and string but can be Integers
and Strings.
