Adversarial Arguments

Problem
A problem is a task that requires a solution

Algorithm
A specific procedure that solves a problem.

A problem can have many algorithms that solve it.

Lower Bound
The lower bound of a problem is the minimum amount of work any algorithm
must perform to solve it.

If an algorithm performs fewer operations than the lower bound,
it must be incorrect.

Adversary
An adversary is a theoretical opponent that chooses inputs strategically
to make the algorithm work as hard as possilbe.

The adversary:
- chooses inputs strategically
- reveals minimal information
- forces the algorithm toward worst-case behavior

Purpose:
Adversarial thinking helps prove lower bounds and analyze worst-case performance.

Example:
Finding the maximum element among n numbers requires at least :
n-1 comparisons.
No algorithm can do better.

Worst Case vs Expected Case
Worst Case
- deterministic guarantee
- adversary forces possible input.
- example: all keys collide in a hash table.

Expected Case
- probabilistic analysis
- assumes random input distribution.
- example: Hash table operations average O(1)

Summary
Adversarial arguments -> worst-case analysis
Expected analysis -> probabilistic analysis.
