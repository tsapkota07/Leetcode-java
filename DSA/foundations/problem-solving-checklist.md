# Problem-Solving Checklist

Before coding, do this.

## Step 1: Understand the Problem

Read it twice.

- What's the input?
- What's the output?
- Constraints? (size, range, etc.)
- Can I modify input?
- Extra space allowed?

Spend 2 minutes here. Saves 20 later.

## Step 2: Work Through Examples

Do it by hand first.

One easy case. One hard case. One weird case if it applies.

Example: Two Sum [2, 7, 11, 15], target = 9
- Easy: [0, 1]
- What if negatives? Duplicates? One element?

## Step 3: Recognize the Pattern

Have you seen this? Is it hashing? Two pointers? Frequency counting?

Check `DSA/patterns/pattern_cheatsheet.md`

If stuck: write out the brute force first. Then optimize.

## Step 4: Estimate Complexity

Before coding:
- Time: O(?)
- Space: O(?)

Does it fit the constraints? If not, different approach.

## Step 5: Code

Implement. Comment as you go. Keep it clean.

## Step 6: Test

Run your examples. Think of edge cases that might break it.

## Step 7: Post-Mortem

Write it in Solution.java:
- Pattern
- Core Idea
- Why brute force fails
- Edge Cases
- Complexity
- Mistakes
- Signal

This builds intuition over time.
